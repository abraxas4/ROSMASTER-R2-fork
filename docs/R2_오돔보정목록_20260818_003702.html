1. 한 줄

매핑 경로에서 오돔 식에 실제로 들어가는 보정 숫자는 4개이고, 전부 기본값(1.0 또는 가정값)입니다. 엔코더 기어비는 이 저장소에 없습니다. 조향각×전진으로 “완벽하게 맞춘” 표는 없습니다. 보드가 준 vy에 1000을 곱해 도(°)로 보고, 축거 0.25 m로 자전거 식을 돌릴 뿐입니다.

3. 코드에 적힌 식

보드:     vx, vy, angular = get_motion_data()
vel_raw:  linear.x = vx
          linear.y = vy * 1000          # 주석: steer angle (도)
          angular.z = angular           # 주석: this is invalued

base_node_R2:
          vx' = vel_raw.linear.x * linear_scale_x     # 1.0
          δ°  = vel_raw.linear.y * linear_scale_y     # 1.0, 이미 *1000 된 값
          L   = 0.25
          R   = L / tan(δ° · π/180)
          ω   = vx' / R
          x  += vx' · cos(heading) · dt
          y  += vx' · sin(heading) · dt
          heading += ω · dt

예: 보드 vy = 0.04 이면 δ = 40°. R = 0.25/tan(40°) = 0.298 m. vx=0.18 이면 ω = 0.60 rad/s ≈ 34°/s. 실제 앞바퀴가 20°만 꺾이면, 같은 식은 각속도를 약 2.3배 과장합니다. 그게 “기어비/스케일이 안 맞다”는 말과 같은 종류의 오차입니다.

그림 1. 조향이 오돔으로 가는 유일한 길. 보정표 없음.

5. 기어비가 소스에 있나

이 포크·야붐 파이썬/C++ 오돔에는 기어비 상수가 없습니다. 바퀴 펄스→m/s 변환은 STM32 펌웨어 get_motion_data() 안에 있습니다. 소스에서 확인·수정할 수 없습니다. B3=1.0 이 “보드가 말한 vx를 그대로 미터로 믿는다”는 뜻입니다.

조향도 마찬가지입니다. 서보 PWM→실제 앞바퀴 각 표가 없습니다. B1이 “보드 vy×1000 = 도”라고 가정합니다. 가정과 실측이 다르면, 결과는 기어비가 틀린 것과 같은 모양으로 나옵니다.

6. 시험 방법과 로그

줄자를 바닥에 붙입니다. 매핑을 켜면 로그가 자동으로 씁니다.

파일: ~/maps/calib_logs/ackermann_YYYYMMDD_HHMMSS.csv
프로그램: scripts/log_ackermann_calib.py (매핑 런치에 포함)

  1. 직진 — 조향 스틱 가운데. 줄자 3.00 m. 멈춤.
  2. 한 바퀴 — 조향을 한쪽으로 고정, 전진. 제자리로 올 때까지 1회전. 바닥 원의 지름을 잽니다.
  3. 직진 복귀 — 다시 조향 가운데, 줄자 3.00 m.

CSV 열 (20 Hz):

7. 숫자로 어디가 틀린지

줄자 값을 로그 옆에 둡니다. 판정은 아래만 봅니다.

구간줄자·바닥로그에서 볼 것판정
직진 3.00 m 3.00 m phase=straight 동안 Δoraw_x (또는 적분 raw_vx·dt) 오돔/줄자. 1.10이면 전진 스케일(기어·B3)이 10% 큼
직진 복귀 3.00 m 3.00 m 같은 비 두 직진 비가 같으면 랜덤이 아님
한 바퀴 바닥 원 지름 D, 회전 1.00 바퀴 평균 delta_deg, 평균 R_m, Δoraw_yaw, ∫imu_wz dt 지름/2 대 R_m. yaw가 360°가 아니면 조향각 가정이 틀림
한 바퀴 중 — 평균 ratio_imu_over_bicycle 0.5면 식이 자이로의 2배로 돎 → ×1000 또는 L이 큼
직진인데 y가 모임 줄자는 직선 phase=straight 인데 |oraw_y| 증가 서보 중립이 0이 아님 (기계 트림) 
전진 스케일 후보  =  줄자 3.00  /  오돔이 센 거리
실제 반지름        =  바닥 지름 / 2
식의 반지름        =  CSV 의 R_m 평균 (circle)
조향각 배율 후보   =  atan(L / 실제R)  /  atan(L / 식의R)
한 바퀴 헤딩       =  oraw_yaw 끝-시작, imu 적분
                     둘 다 ≈ ±360° 이어야 식·자이로가 맞음
