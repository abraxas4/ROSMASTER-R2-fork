SSH 열쇠와 자물쇠

로버에서 GitHub로 코드를 올릴 때 쓰는 인증을, 집 열쇠로 풀어 쓴 설명입니다.

1. 왜 이게 필요했나

로버(Jetson)에서 문서를 고친 뒤 GitHub에 올리려면, GitHub가 “이 컴퓨터가 주인 맞아?”를 확인해야 합니다.

Chrome에 로그인하는 것은 웹페이지용입니다. 터미널의 git push는 Chrome 쿠키를 보지 않습니다. 그래서 터미널용 열쇠가 따로 필요합니다. 그 방식이 SSH 키입니다.

2. 열쇠와 자물쇠는 한 쌍

SSH 키를 만들면 파일이 두 개 생깁니다. 항상 같이 태어납니다.

비유파일하는 일누구에게 주나
자물쇠 공개키 .pub 문을 잠그는 쪽. 보여 줘도 됨 GitHub에 등록
열쇠 비밀키 (확장자 없음) 문을 여는 쪽. 이 컴퓨터 안에만 아무에게도 안 줌. 채팅에도 안 붙임

자물쇠만 있으면 열 수 없습니다. 짝이 되는 열쇠가 그 컴퓨터 안에 있어야 문이 열립니다.

그림 1. 로버가 GitHub에 올릴 때: 로버의 열쇠 ↔ GitHub의 자물쇠

3. 어디에 두나

이 프로젝트에서 컴퓨터가 두 대입니다. 열쇠는 컴퓨터마다 하나씩 두는 것이 보통입니다.

컴퓨터열쇠(비밀키) 위치자물쇠(공개키)를 걸어 둔 곳열리는 문
개발 PC PC의 ~/.ssh/ ① 로버 authorized_keys
② (있을 수 있음) GitHub		 PC → 로버 SSH 접속
PC → GitHub 푸시
로버 Jetson ~/.ssh/id_ed25519_github GitHub 계정 SSH keys 로버 → GitHub 푸시

4. 키가 이미 있는데 왜 또 만드나

GitHub에 이미 있던 키는 대개 PC 열쇠의 자물쇠입니다. 그 짝 열쇠는 PC 안에만 있습니다.

로버에서 푸시하려면 로버 안의 열쇠가 필요합니다. PC 열쇠를 로버로 복사하지 않습니다. 대신 로버용 열쇠를 하나 더 만들고, 그 자물쇠만 GitHub에 추가합니다.

GitHub는 자물쇠를 여러 개 걸 수 있습니다. 예전 PC 키는 그대로 두면 됩니다.

그림 2. 컴퓨터마다 열쇠 하나. GitHub에는 자물쇠를 여러 개 걸어 둠

5. 우리가 한 일
