1. 한 장 요약

질문답
조이스틱으로 지도가 그려진다. 입력이 잘 오나? 지도가 늘어나면 라이다·카메라·오도메트리가 들어오고 있다는 뜻입니다. “잘” 오는지는 Hz를 재봐야 합니다. 확인 명령은 7장.
카메라 + 라이다 + 앞바퀴 조향 + 뒷바퀴 구동, 이 4개로 맵핑하나? 아니요. 맵을 그리는 센서는 카메라(RGB+깊이)와 라이다입니다. 앞조향·뒷구동은 움직이는 액추에이터입니다. 바퀴 회전량과 IMU는 위치(오도메트리)를 만드는 보조 입력입니다.
IMU 등 센서도 보정하나? 매핑 시작 때 자동 보정은 하지 않습니다. IMU는 Madgwick 필터 + EKF로 융합만 합니다. 카메라 내부 파라미터는 Astra 드라이버가 실어 줍니다. 바퀴 스케일 보정 스크립트는 있으나 지금 스택에서 자동 실행되지 않습니다.
Git은 어디? 메인: /home/jetson/ROSMASTER-R2-fork → GitHub abraxas4/ROSMASTER-R2-fork. 실제로 돌아가는 ROS 패키지는 ~/yahboomcar_ros2_ws (이 폴더 자체는 git 저장소가 아님).
바탕화면에서 기존 맵에 계속 학습? 신경망을 학습시키는 것이 아닙니다. RTAB-Map이 기존 DB에 노드를 이어 붙이는 증분 SLAM입니다. 아이콘 이름: R2 매핑 이어서.
ROS 2 매핑에 GPU AI 러닝이 있나? 없습니다. 고전 특징점 + 스캔 정합 SLAM입니다. Jetson GPU로 YOLO/MediaPipe를 돌리는 패키지는 워크스페이스에 있지만, 매핑 launch는 켜지 않습니다.
10평 한 바퀴에 배터리가 끝나고 더 느려진다 느린 조이스틱 설정(0.2 m/s)과 전압 강하로 모터가 힘 빠지는 현상이 겹친 것으로 보입니다. Jetson은 지금 MAXN_SUPER(최고 전력)입니다. 느리게 한 것 자체는 맵 품질에 이롭고, 방전 직전 속도 저하는 품질을 해칩니다.

앞에서 말한 네 가지는 역할이 둘로 갈립니다.

6. GPU AI 러닝을 쓰나?

결론 지금 ROS 2 매핑 파이프라인에는 GPU로 신경망을 학습하거나, 학습된 네트워크로 지도를 그리는 단계가 없습니다. “이어서 학습”은 일상 말이지, PyTorch/TensorRT 학습 루프가 아닙니다.
구분매핑 스택 (지금)워크스페이스에만 있는 것
알고리즘 RTAB-Map — 특징점 + 라이다 ICP + 그래프 최적화 MediaPipe, YOLOv5, KCF 트래커, 색 추적
학습(backprop) 없음 별도 데모에서만. 매핑 launch에 없음
추론(inference) 고전 OpenCV 특징. GPU 필수 아님 손/얼굴/객체 인식 시 GPU를 쓸 수 있음
Jetson GPU 켜져 있음(MAXN_SUPER). 매핑이 그걸 쓰라고 요청하지는 않음 카메라 ISP/디스플레이가 일부 GPU를 쓸 수는 있음
DB가 커지는 이유 이미지·스캔·그래프 노드를 SQLite에 저장 모델 가중치 업데이트가 아님

근거가 되는 launch 설정:

  • Mem/UseGPU, SuperPoint, TensorRT, CUDA 특징 추출 플래그 — 설정되어 있지 않음
  • 구독은 RGB-D, 스캔, 오돔뿐
  • 순찰용 Nav2도 고전 지역 플래너(DWB). 학습 네트워크 아님
그래서 맵 품질은 무엇을 바꾸나 속도·조명·루프(같은 길 다시 지나기)·배터리 전압이지, “더 오래 학습시킬수록 똑똑해지는” 구조가 아닙니다. 같은 복도를 천천히 왕복하면 루프 클로저가 그래프를 고쳐 맵이 반듯해질 수는 있습니다. 그건 최적화이지 딥러닝이 아닙니다.

7. 입력이 잘 들어오는지 확인하는 법

지도가 보인다는 것은 “뭔가 들어온다”는 뜻입니다. 아래 숫자가 나와야 “잘” 들어옵니다.

토픽의미권장 최소 Hz정상이면
/camera/color/image_rawRGB10 (보통 25–30)화면이 끊기지 않음
/camera/depth/image_raw깊이33D가 채워짐
/rgbd_image색·깊이 동기3RTAB-Map이 프레임을 받음
/scan라이다3 (보통 ~10)벽이 선으로 보임
/odomEKF 위치3로봇 점이 따라옴
/imu/data_rawIMU 원시10기울이면 값이 변함
/joy패드스틱 움직일 때버튼·축이 변함

그림 4. 맵이 보이면 입력은 있다. 품질 판단은 주파수와 화면 왜곡으로.

조향·구동이 “입력으로 잘 오나” 보는 법

  • START를 누른 뒤 스틱을 밀 때 /cmd_vel의 linear.x(전후), linear.y(조향)가 변하면 패드→ROS는 정상입니다.
  • 바퀴가 도는데 /odom이 안 움직이면 오도메트리 쪽 문제입니다.
  • 앞바퀴가 안 꺾이면 서보·전원·linear.y를 의심합니다. 맵 알고리즘 문제가 아닙니다.

8. IMU와 센서 보정을 하나?

짧게: 실시간으로 돌리는 것은 ‘융합’이지 ‘캘리브레이션 루틴’이 아닙니다.

센서지금 하는 일자동 보정?어디에 있나
IMU 원시값 발행 → Madgwick(use_mag: false) → EKF가 /odom_raw와 합침 아니오 imu_filter_param.yaml, ekf_x1_x3.yaml
지자계 /imu/mag는 발행하지만 필터가 사용 안 함 아니오 실내 자장 왜곡 때문에 끈 설정
카메라 내부변수 Astra 드라이버가 camera_info에 실어 줌 공장값. 체스보드 재보정 없음 astro_pro_plus.launch.xml
라이다 위치 고정 TF: 앞으로 4.35 cm, 위로 11 cm 수동 상수 laser_bringup_launch.py
바퀴 스케일 bringup에서 linear_scale_x/y = 1.0 스크립트는 있음, 자동 실행 없음 calibrate_linear_R2.py, calibrate_angular_R2.py
RTAB-Map ↔ IMU 직접 연결 없음. 중력 제약 0 — Optimizer/GravitySigma: 0
보정하면 좋아지는 경우 직진했는데 맵이 부채처럼 벌어지거나, 제자리 회전이 각도보다 크면 바퀴 스케일 보정이 도움이 됩니다. IMU 자체 8자 보정·자침 보정은 현재 매핑 절차에 들어 있지 않습니다.

10. 전원이 금방 닳고 차가 느려지는 이유

두 현상을 한 원인으로 보면 안 됩니다.

현상원인맵 품질과의 관계
처음부터 느리다 조이스틱 한도 xspeed_limit = 0.2 m/s. 기어 내리면 0.05 m/s. 데드존 0.45라 스틱을 깊게 밀어야 함 느린 것은 RTAB-Map에 이롭다 (흔들림·블러 감소)
돌다 보면 더 느려진다 배터리 전압이 떨어지면 같은 PWM에서도 모터 토크가 줄어듦. 보드가 저전압 보호에 들어가면 더 굼떠짐 오돔이 들쭉날쭉해져 맵이 나빠짐
10평 한 바퀴에 끝난다 Jetson이 MAXN_SUPER(최고 전력) + 화면 + 라이다 + 카메라 + 모터. 배터리 용량·노후·충전 부족이 겹치면 수분~수십 분이면 방전 한 번에 집을 다 못 그림 → ‘이어서’로 쪼개야 함
그림 5. 3셀(약 11.1 V 공칭) 리튬 기준. 정확한 공칭은 배터리 라벨을 보세요.

문서 작성 시각에 확인한 것

  • ROS 매핑 노드는 당시 꺼져 있었습니다. OLED 프로세스만 동작.
  • 모터보드에 직접 물었을 때 battery=0.0, version=-1. 차체 스위치가 꺼졌거나, OLED가 시리얼을 잡고 있거나, 보드가 응답하지 않는 상태입니다. 지금 용량이 0이라는 뜻으로 단정하지 마세요. 매핑을 켠 뒤 /voltage를 보세요.
  • Jetson 전력 모드: NV Power Mode: MAXN_SUPER — 성능 최대, 전류도 최대.

전원을 늘리려면 (우선순위)

  1. 출발 전 만충. 매핑 중 /voltage가 11.4 V 아래로 가면 충전으로 돌아가기.
  2. 화면 밝기 낮추기. 매핑이 아닌 시간에는 R2 매핑 중지.
  3. Jetson을 최고 모드로 두지 않기. 예: sudo nvpmodel -m 2 후 가능한 15 W/10 W 모드 확인. (모델마다 번호가 다름. nvpmodel -q --verbose)
  4. 한 번에 집을 다 그리지 말고, 방 하나 → 중지 → 충전 → 이어서.
  5. 배터리 라벨 용량(예: 12 V 3 Ah vs 5 Ah)과 연식을 확인. 10평 한 바퀴에 끝나면 용량 부족 또는 셀 노후 가능성이 큼.
느리게 둔 것이 맵을 망쳤을까? 아닙니다. 0.2 m/s 전후는 실내 RTAB-Map에 흔한 속도입니다. 품질이 나쁘다면 원인 후보는 오히려 방전 직전 속도 출렁임, 시작 위치 어긋난 ‘이어서’, 조명, 유리·거울, 같은 길 미방문(루프 없음)입니다. 더 늦출 필요는 없고, 전압이 버틸 때 일정한 느린 속도가 정답입니다.
